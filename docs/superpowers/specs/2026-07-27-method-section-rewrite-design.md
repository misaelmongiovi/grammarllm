# Method section rewrite — design

Date: 2026-07-27
Target file: `GrammrRL/CameraReady2027.tex`, `\section{Method}` (lines 191–261 of the
current draft).

## Goal

Make the Method section describe the algorithm the code actually implements, at the
level of abstraction a reader needs, and state the *final* formulation of the
estimators rather than the historical one. Results are explicitly out of scope: the
reported numbers come from earlier runs and will be regenerated, so this rewrite does
not touch Results, Experimental Setup, or the appendix table.

## What is wrong with the current text

Established by reading `GrammrRL/core/{rl_trainer,rollout,reward,policy_batched_multi}.py`
and the `config_snapshot.yaml` of the reported runs.

1. **Factually wrong.** The current text says the beam target $Y^\star$ is "obtained
   with the reference decoder". It is not: `collect_batch` calls `compute_group` on the
   model with the LoRA adapters live, so $Y^\star$ is generated by the *current policy*
   and moves as training proceeds.
2. **Superseded estimators.** The loss is written with a length-normalized policy
   gradient and a plain KL term. The code's final formulation is the summed estimator
   (`pg_norm="sum"`, no per-candidate length denominator) and Schulman's k3 KL
   (`kl_estimator="k3"`), added because the length denominator under-weights longer
   candidates inside a group and because the signed k1 form can go negative per sample
   and push the policy *away* from the reference.
3. **Wrong emphasis.** "Implementation note: trailing-pad contamination" is a
   subsection of its own for what is one property of the reward definition.
4. **Overclaim by omission.** "verified bit-exact against a reference per-candidate
   implementation" is true only for per-candidate scoring; the batched path drifts in
   bf16. The rewrite drops the bit-exactness claim rather than qualifying it, since
   scoring granularity is below the level this section works at.

## Scope decisions

- Method presents k3 + summed policy gradient as *the* algorithm. No historical
  framing, no ablation branch.
- No implementation minutiae: no padding regimes, no scoring granularity, no
  tolerances, no dedup switch, no batch shapes. Those live in the code and, if needed,
  in the appendix.
- Four subsections: Setup and objective / Rollout / Reward / Loss. The trailing-pad
  point becomes one clause inside Reward.
- Hyperparameter values stay in Experimental Setup, not here.

## Replacement text

```latex
\section{Method}

\subsubsection{Setup and objective.}
Let $G$ be a formal grammar and $\mathcal{M}(y_{<t}) \subseteq V$ the set of
tokens admissible at step $t$ given the prefix $y_{<t}$. Constrained decoding
samples or maximizes over the masked distribution
\begin{equation}
\pi^{G}_\theta(y_t \mid x, y_{<t}) =
\frac{\pi_\theta(y_t\mid x,y_{<t})\,\mathbb{1}[y_t \in \mathcal{M}(y_{<t})]}
     {\sum_{v \in \mathcal{M}(y_{<t})} \pi_\theta(v\mid x,y_{<t})}.
\end{equation}
Beam search with width $K$ approximately maximizes $\log \pi^{G}_\theta(y\mid x)$
over full sequences; greedy decoding maximizes it one step at a time. The gap
between them is the object of study. GrammarRL seeks parameters $\theta'$ such
that
\begin{equation}
\arg\max\nolimits_{y}^{\text{greedy}} \pi^{G}_{\theta'}(y \mid x)
\;\approx\;
\arg\max\nolimits_{y}^{\text{beam-}K} \pi^{G}_{\theta}(y \mid x),
\end{equation}
i.e.\ the trained policy's \emph{first} choice is the untrained policy's
\emph{searched} choice. Only a small set of adapter parameters is trained; the
pretrained weights stay frozen and serve throughout as the reference policy
$\pi_{\text{ref}}$.

\subsubsection{Rollout: the particles-plus-beam group.}
For each prompt we build an RLOO candidate group by composing two sources: $N$
grammar-constrained sampled particles, and one beam-search target $Y^\star$. Both
are produced by the \emph{current} policy, so the group spans a \emph{negative
pole} --- sampled particles whose quality tracks current greedy behaviour --- and
a high-reward target that is itself the policy's own searched answer. Training
therefore chases a moving target: as the policy improves, so does the beam output
it is asked to internalize. This contrast is what the leave-one-out advantage
needs in order to have signal.

We stress this design choice because the natural alternative fails. A composition
built from a single wide beam, deduplicated by text, collapses training quality:
all candidates are already good, so re-ranking them by log-probability carries
almost no information about task correctness, and the advantages become noise.
All results in this paper use the particles-plus-beam composition.

\subsubsection{Reward: reference-anchored and label-free.}
Each candidate $y^{(i)}$ receives
\begin{equation}
r^{(i)} = \frac{1}{|y^{(i)}|}\sum_{t}\log \pi^{G}_{\theta_{\text{ref}}}\!\left(y^{(i)}_t \mid x, y^{(i)}_{<t}\right),
\end{equation}
the length-normalized grammar-masked log-probability under the frozen reference
policy, computed over the candidate's own tokens only --- generation padding is
discarded before scoring, so the reward measures content and not how long a batch
happened to be. Anchoring on the reference rather than on the policy's own
log-probability prevents the trivially gameable solution in which the policy
inflates its own likelihood; the reference score is a fixed, external notion of
``plausible under the pretrained model''. Crucially, no gold label is ever
consulted. RLOO converts rewards into advantages by leave-one-out baselining
within the group, $A^{(i)} = r^{(i)} - \frac{1}{n-1}\sum_{j\neq i} r^{(j)}$.

\subsubsection{Loss.}
The update is a grammar-masked policy gradient \citep{williams1992simple} with a
KL anchor to the reference policy:
\begin{equation}
L = \operatorname{mean}_i\!\left(-A^{(i)} \log \pi^{G}_\theta(y^{(i)}\mid x)\right)
+ \beta\,\operatorname{mean}_i D^{(i)}_{\mathrm{KL}}.
\end{equation}
The policy-gradient term is the summed sequence log-probability, with no
per-candidate length denominator. Dividing each candidate by its own length --- the
conventional choice --- scales the per-token gradient of a long candidate down
relative to its shorter siblings in the same group, systematically under-weighting
exactly the more fragmented outputs whose advantage the group was constructed to
express.

For the KL term we use the low-variance estimator of \citet{schulman2020kl},
\begin{equation}
D^{(i)}_{\mathrm{KL}} = e^{\rho_i} - \rho_i - 1,
\qquad
\rho_i = \frac{1}{|y^{(i)}|}\left(\log \pi^{G}_{\text{ref}}(y^{(i)}) - \log \pi^{G}_{\theta}(y^{(i)})\right),
\end{equation}
rather than the signed difference $\log\pi_\theta - \log\pi_{\text{ref}}$. The
signed form is unbiased only in expectation: on any individual sample on which the
policy scores below the reference it is negative, so $\beta\,\mathrm{KL}$ lowers
the loss and the regulariser becomes an accelerant away from the reference. The
estimator above is non-negative for every sample and has the correct gradient sign.
Both terms are evaluated under the grammar mask, so the objective is defined on the
same constrained distribution that decoding will use.
```
